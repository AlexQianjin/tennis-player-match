网球约球匹配微信小程序
状态机流转图说明
版本：V1.0  |  核心对象：约球需求、申请记录、到场确认
1. 状态机概述
本文档描述三个核心实体的状态流转：约球需求（match_request）、申请记录（application）、到场确认（attendance）
状态变更必须通过明确的业务动作触发，禁止直接修改状态
所有状态变更需记录操作日志（建议单独日志表）

4. 到场确认状态机（attendance）
4.1 状态定义
字段
取值
说明
arrived
0 / 1
0=未确认，1=已确认到场
rating
null / 1-5
仅在双方 arrived=1 后可填写
4.2 流转规则
约球状态变为「已匹配」时，为双方各创建一条 attendance 记录（arrived=0）
用户点击「已到场」→ 对应记录 arrived=1，记录 arrived_time
当双方 arrived 都为 1 时 → 约球状态变为「已完成」，允许评分
评分提交后不可修改，更新对方 avg_rating

6. 关键约束与异常处理
同一用户同时只能有一个 status in (1,2) 的约球需求
同一用户对同一约球只能申请一次（application 唯一索引保证）
仅在约球状态为「已匹配」且当前时间 ≥ 约定时间时，才允许点击「已到场」
仅在双方都确认到场后，才允许提交评分
状态变更需加分布式锁或数据库乐观锁，防止并发问题
