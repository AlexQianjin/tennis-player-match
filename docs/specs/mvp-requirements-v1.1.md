网球约球匹配微信小程序
MVP 完整需求文档
版本：V1.1  |  测试城市：武汉  |  日期：2026年11月
1. 用户流程图
1.1 新用户注册流程
打开小程序 → 微信授权登录
填写个人资料（头像、昵称、NTRP、性别、年龄、城市、打球风格、简介）
选择城市（武汉）
资料保存成功 → 进入首页推荐列表
1.2 发布约球流程
首页点击「发布约球」
填写：日期、时段、球场、人数（单打/双打）、期望等级范围、性别偏好
提交发布（同时只能发布一个）
发布成功 → 出现在推荐列表中，状态为「待匹配」
1.3 申请与匹配流程
用户在推荐列表浏览卡片（上下滑动）
点击卡片查看详情 → 点击「申请加入」
发布方收到申请 → 进入「我的约球-待确认」
发布方点击「同意」→ 匹配成功，双方进入「已确认」状态
发布方点击「拒绝」→ 申请失败，申请方收到结果
1.4 到场确认与评分流程
约定时间到达后，双方均可点击「已到场」
双方都点击后 → 状态变为「已完成」
双方可互相评分（1-5星）
评分完成后获得信用分 +1
若24小时内无人确认 → 自动变为「已取消」（不计入取消次数）

3. 页面原型描述
3.1 首页（推荐列表）
顶部：城市选择器 + 筛选按钮
主体：约球卡片列表（上下滑动）
卡片内容：头像、昵称、NTRP、信用分、球场、时间、性别
底部Tab：首页 / 发布 / 我的约球 / 个人中心
筛选面板：等级范围、性别、时间、球场
3.2 约球详情页
发布者信息：头像、昵称、NTRP、信用分、平均评分、打球风格、简介
约球信息：日期、时段、球场名称与地址、人数、期望条件
底部按钮：「申请加入」或「已申请/已匹配」状态
3.3 发布约球页
日期选择器
时段选择（预设时段或自定义）
球场选择（下拉列表，仅武汉已有球场）
人数选择：单打 / 双打
期望等级范围（滑块或选择）
性别偏好
底部：「发布」按钮
3.4 我的约球页
顶部Tab：待确认 / 已确认 / 已完成 / 已取消
列表项：对方头像昵称、时间、球场、状态
操作按钮：同意/拒绝、取消、已到场、评分
3.5 个人中心
头部：头像、昵称、NTRP、信用分、平均评分
入口：我发布的、我申请的、已匹配成功的
入口：编辑资料、设置
4. 异常场景处理
4.1 匹配相关异常
异常场景
处理方式
用户已有进行中的约球时再次发布
提示「您已有一个进行中的约球，请先完成或取消」
申请已匹配成功的约球
按钮置灰，显示「已匹配」
发布方拒绝申请
申请方状态变为「已拒绝」，可继续申请其他约球
匹配成功后一方取消
记录取消次数，另一方状态变为「已取消」，可重新发布
同一用户对同一约球重复申请
提示「您已申请过该约球」
4.2 到场与评分异常
异常场景
处理方式
仅一方点击「已到场」
等待另一方，不触发评分和积分
约定时间后24小时无人确认
自动变为「已取消」，不计入取消次数
双方都确认后一方未评分
允许稍后评分，不影响对方积分
评分时网络异常
本地缓存，恢复后重试提交
4.3 资料与等级异常
异常场景
处理方式
冷却期内修改NTRP
提示「每月仅可修改一次，请于X月X日后修改」
NTRP输入超出1.0-7.0
前端限制，仅允许合法范围
未完善资料时发布约球
引导完善资料后再发布
4.4 系统异常
异常场景
处理方式
网络断开
提示「网络异常，请检查后重试」，支持下拉刷新
球场数据加载失败
显示缓存数据或提示「球场信息加载中」
微信授权失败
引导用户重新授权
5. 关键业务规则汇总
硬性匹配：NTRP ±0.5 + 时间完全重合 + 同一球场
信用分 = 确认到场次数 - 取消次数（最低0）
推荐排序：信用分高优先 + 等级更接近优先
同时仅能发布一个约球需求
双方都点击「已到场」后才能评分和获得积分
NTRP每月仅可修改一次
评分公开展示平均分，不显示具体评分人
